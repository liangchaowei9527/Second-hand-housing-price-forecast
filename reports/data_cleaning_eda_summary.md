# 数据清洗与核心 EDA 阶段总结

## 1. 这一阶段做了什么

这一阶段的目标是把标准化后的 Anjuke 原始数据合并成统一数据集，完成基础清洗，并产出能够支撑后续分析的核心 EDA 图表。

最终落地的结果包括：

- 统一数据集：`data/processed/anjuke_merged_standardized.csv`
- 清洗后数据集：`data/processed/anjuke_cleaned.csv`
- 核心 EDA 图表：`reports/figures/`

## 2. 遇到的主要问题

### 2.1 标准化后关键字段大量为空

最开始运行标准化脚本后，合并结果里 `area_sqm`、`total_price_wan`、`build_year`、`region` 等关键字段几乎全是空值，导致清洗阶段把样本全部过滤掉，最后得到空的数据集。

### 2.2 字段映射没有真正命中原始列名

问题根因不是清洗逻辑本身，而是原始 CSV 的中文列名和脚本里的候选映射不完全一致。比如：

- `总面积`、`总面 积`、`建造年份`、`价格` 这类列名没有完全覆盖
- `区`、`街道` 等字段没有统一口径
- `house_price_raw.csv` 和 `dataset.csv` 的字段风格也不完全一致

这导致脚本虽然能生成文件，但核心数值字段并没有被正确提取出来。

### 2.3 标准化脚本把自己生成的文件又当成输入

当脚本以 `data/raw` 目录为输入时，会把之前生成的 `anjuke_ingested_*.csv` 也重新扫进去，造成目录递归污染，输出文件越来越多，排查也越来越困难。

### 2.4 清洗和 EDA 的边界条件没有处理好

基础 EDA 中的缺失值图在“没有缺失值”的情况下会触发空轴绘图报错，导致整个清洗流程中断。

### 2.5 直接运行脚本时出现模块导入问题

`clean.py` 直接作为脚本执行时，`src` 包不在 Python 搜索路径里，出现了 `ModuleNotFoundError: No module named 'src'`。

## 3. 我是怎么解决的

### 3.1 先确认问题到底出在标准化还是清洗

我先检查了原始 CSV 的表头，再回看标准化后的文件头部和非空统计，确认问题是在标准化阶段就出现了，而不是清洗规则太严。

### 3.2 补全字段映射，并改成向量化处理

我把 `ingest_kaggle_anjuke.py` 里的字段候选列表补全到中文列名，并将处理方式改成向量化，而不是逐行 `iterrows()` 处理。

这样做有两个效果：

- 能正确命中 `总面积`、`价格`、`建造年份`、`小区`、`区` 等字段
- 处理速度明显更稳定，不会在大表上卡住

### 3.3 排除标准化输出文件，避免递归处理

我修改了目录扫描逻辑，只保留原始输入文件，排除 `anjuke_ingested_*.csv` 这类已经生成的标准化结果，避免脚本把自己的输出再次当输入。

### 3.4 让清洗脚本只合并每个来源的最新版本

由于 `data/raw` 里会保留历史输出，我在清洗脚本里增加了“按来源文件选最新版本”的逻辑，避免旧的错误结果污染当前合并数据集。

### 3.5 补上脚本直跑时的导入路径

为了让 `clean.py` 在命令行里直接执行时也能导入 `src.visualization.charts`，我增加了运行上下文判断，并把仓库根目录临时加入 `sys.path`。

### 3.6 修复 EDA 的边界报错

在缺失值全为空的情况下，我把缺失值图改成先判断是否有非零缺失率：

- 如果有缺失值，就正常画条形图
- 如果没有缺失值，就显示 “No missing values” 提示

这样避免了 `pandas` 绘图在空序列上报错。

### 3.7 补齐数据清洗逻辑

清洗阶段主要做了这些处理：

- 文本列去空格和空字符串标准化
- 数值列统一转换为数值类型
- 删除 `total_price_wan` 或 `area_sqm` 缺失、为 0 或非法的记录
- 从 `floor` 字段中识别 `2024年建造` 这类文本并回填 `build_year`
- 对异常放大的 `unit_price_yuan_per_sqm` 做 10000 倍回缩和重算
- 衍生 `house_age` 和 `price_per_sqm_wan`
- 去重并按区域、小区、总价排序

## 4. 最终结果

当前这一步已经完成到可交付状态：

核心 EDA 图包括：

## 5. 这一阶段的经验

这一阶段最关键的经验是：先确认字段是否真的被正确抽取，再谈清洗规则是否合理。只要标准化阶段漏掉了核心字段，后面的清洗和分析就会全部失效。

另外，数据处理脚本最好满足三个条件：

- 能直接作为脚本运行
- 能处理大文件而不依赖逐行逻辑
- 能识别并跳过自己生成的中间结果
